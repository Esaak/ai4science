# Данные проекта

Единица данных — **сцена**: один трассер одного прогона LES. Сетка 128×128, ячейка 2 м,
область 256×256 м. Концентрация — в единицах LES, не нормирована.

## `top_fields.npz` — полные поля пяти сцен

| массив | форма | что это |
|---|---|---|
| `idx` | (5,) | номера сцен в `val.npz`: 6792, 3419, 2446, 3197, 10339 |
| `x` | (5, 9, 128, 128) | вход модели |
| `t` | (5, 5, 128, 128) | таргет LES |
| `p_прежняя` | (5, 5, 128, 128) | предсказание прежней модели |
| `p_combo` | (5, 5, 128, 128) | предсказание модели `combo` |

**Это пять сцен с наибольшей ошибкой, а не случайная выборка.** Любые метрики по этому
файлу характеризуют худший случай, а не модель: общий R² по пяти сценам у `combo` равен
−1.97, у прежней −2.72, тогда как на всей val у `combo` R² = 0.874
(`urban_layer/docs/state.md`, обновлено 2026-10-17). Переносить числа из этого файла на
качество модели нельзя.

Семейства пяти сцен: 6792, 3419, 2446 — январские (`2026_01_*`); 3197, 10339 —
`urban_layer_*`. Семейство определяется по полю `campaign` в `val.npz`: префикс `2026_01`
означает январское.

### Каналы входа `x`

| канал | что в нём |
|---|---|
| `x[0]` | высота зданий, делённая на 64 м |
| `x[1]` | расстояние до здания |
| `x[2]` | растительность, LAI (интеграл листвы по столбу ячейки) |
| `x[3]` | источник эмиссии |
| `x[4]` | расстояние до источника |
| `x[5]`, `x[6]`, `x[7]` | cos, sin и модуль градиента давления (модуль — константа) |
| `x[8]` | константа на сцену; в описании входа модели её нет |

Высот растительности во входе нет: `x[2]` — интеграл по столбу, низкую густую изгородь и
высокое редкое дерево по входу не различить.

### Слои таргета `t` и предсказаний `p_*`

| индекс | слой | высота |
|---|---|---|
| 0 | Z1 | 3 м |
| 1 | Z5 | 11 м |
| 2 | Z8 | 17 м |
| 3 | Z25 | 51 м |
| 4 | Mean | среднее по высоте |

Под зданиями в Z1 и Z5 стоят нули — это не пропуски. Нулевых ячеек в таргете 3.9 %.

## `val.npz` — таблица сцен

11 632 сцены val (534 прогона: 6 176 январских, 5 456 `urban_layer_*`), по строке на сцену.
Полей целиком здесь нет, только агрегаты.

| массив | форма | что это |
|---|---|---|
| `files` | (11632,) | путь к `.npz` сцены в хранилище |
| `num` | (11632, 30) | числовые признаки, названия столбцов — в `cols` |
| `cols` | (30,) | `src_cells`, `src_ncc`, `src_full`, `src_vert`, `src_horiz`, `src_ncomp`, `q_max`, `q_sum`, `ln_s`, `src_row`, `src_col`, `src_row_min`, `src_row_max`, `src_col_min`, `src_col_max`, `wind_cos`, `wind_sin`, `wind_mag`, `lai_mean`, `lai_frac`, `lai_src`, `sdf_src`, `build_frac`, `y_mean`, `y_max`, `cov01`, `cov1`, `frac100`, `com_row`, `com_col` |
| `y_layer_mean` | (11632, 5) | среднее по каждому слою |
| `y_layer_max` | (11632, 5) | максимум по каждому слою |
| `campaign`, `exp`, `tracer` | (11632,) | набор, прогон LES, номер трассера |
| `h_x`, `h_src`, `h_build`, `h_lai` | (11632,) | хэши входа, источника, застройки, растительности |

Средние по слоям в `y_layer_mean` совпадают со средними по полям из `top_fields.npz` с
относительной точностью 6·10⁻⁸ — это независимая сверка двух файлов.

## `probe_fields.npz` — полные поля двух сцен

Ключи вида `<сцена>__<массив>`, сцены — `типичная` и `сильный_факел`. Массивы: `les`
(поле LES), `raw` и `qmap` (два варианта предсказания), `valid` (5, 128, 128) — маска
значимых ячеек, `build` — маска застройки, `wind` — три числа, `r2`, `scene`.

Ловушка: поле `__scene` — это позиция в подвыборке, а не номер сцены в val; настоящие
номера — 1434 и 1644.

## Чего в этих данных нет

- Полных полей больше пяти плюс двух: всё, что требует таргета целиком по многим сценам,
  считается только на сервере, на хранилище `/storage/thalassa`.
- Весов моделей и логов обучения: `outputs/` в git исходного проекта не входит.
- Новой выборки `build_dataset_v1` (175 застроек) — она отложена решением от 2026-10-12.

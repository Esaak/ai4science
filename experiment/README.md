# Воспроизведение парного сравнения

Из корня репозитория с установленными зависимостями:

```bash
.venv/bin/python -m experiment.compare_centroids
```

Скрипт прогоняет синтетические проверки и сохраняет `results/paired_errors.csv`
и `results/provenance.json` в этом каталоге. `--pilot` считает только
`geometry_id=150` и печатает результат. Для повторного полного прогона в отдельный
каталог можно передать `--output-dir PATH`. Интернет и SSH для расчёта не нужны.

## Входы

- LES, DL и общая маска слоя Z1 взяты из `../fixtures/hw2/plumes.npz`.
  Скрипт проверяет архив по манифесту ДЗ2, затем сопоставляет сцены по паре
  `(geometry_id, scene_name)` и сверяет SHA-256 исходных сцен. Для всех
  25 сцен сохранённая маска совпала с маской по высотам зданий в исходных
  файлах.
- `gaussian_inputs.json` получен из 25 исходных файлов в
  `urban_layer_v1_npz/val` на `edison`. Первые две компоненты `wind`
  задают направление градиента, их совпадение с каналами входа проверено
  по каждой сцене. Перенос направлен против градиента. Направления из
  `wind` и из `meta.dPdx` / `meta.dPdy` различаются максимум на 0,303°
  по этой выборке.
- Границы дорожных боксов взяты из `meta.source_boxes`. Веса рассчитаны
  как `(x1 − x0) × (y1 − y0)² × 8 м × meta.emis_coeff` по конфигурации
  LES и `get_maps_v1.py::source_maps`. Проверка восстановила исходный
  растр `power`, включая суммирование в пересечениях. Для расчёта поля
  мощность каждого бокса распределяется по пересечениям бокса с ячейками,
  пропорционально площади пересечения. Точечное ядро помещается в центр
  каждого пересечения.
- В `gaussian_config.json` записаны настройки утверждённого протокола.

По каждой из 25 сцен таблица содержит ошибки центра в метрах
`e_DL`, `e_Gaussian` и их разность `d = e_Gaussian − e_DL`. Метаданные
прогона содержат хеши входов, кода и таблицы, версии Python и NumPy.
Протокол и ограничения описаны в [постановке исследования](../research/problem.md).
Перед включением результатов в статью требуется верификация автора.
